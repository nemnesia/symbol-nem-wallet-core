# 0.2.0 への移行

0.2.0 は Node.js / Browser / React Native Android / iOS の配布対象を含むリリースです。
Rust crate、npm package、React Native の Podspec は `0.2.0` に揃えます。

## 新規 Profile の確定

`finalize_generated_profile` の入力は `store`、`pending_profile`、`password_utf8` の3引数です。
0.1.0 の第4引数 `handoff_confirmation` と、Rust / TypeScript の
`HandoffConfirmation`、`HandoffConfirmationStatus` は削除されました。
呼出し側は確認引数を削除し、Application 自身が現在の操作で次を完了してから確定を要求してください。

1. `prepare_generated_profile` が返した完全な Mnemonic を意図した利用者へ提示する。
2. 利用者から明示的な受領確認を取得する。
3. 確認成立時だけ同じ Store、Pending Profile、password で確定を要求する。

拒否・中断・確認未取得の場合は確定を呼び出さず、Profile 作成を成功扱いしません。
確認を常に成功させる実装や、以前の受領確認の再利用はしないでください。
Core は Pending Profile の認証・対象 Store との整合性を検証しますが、
Application が提示・受領確認を実施したことは独立検証しません。
正しい Pending Profile と password を持つ Application は確認なしでも確定を呼べるため、
確認後だけ呼ぶ制御を Application に実装する必要があります。
安全な利用例は [npm package README](../../packages/wallet-core/README.md#新規-wallet-を作る) にあります。

Native C ABI の `snwc_finalize_generated_profile` も確認入力が削除されています。
出力引数の位置が変わるため、0.2.0 の header と library を組み合わせ、呼出し側を再ビルドしてください。
WASM / Node / React Native の生成物も同じ版のものを使用してください。

## npm の定数

package root から `Network.TESTNET` / `Network.MAINNET` および
`Chain.NEM` / `Chain.SYMBOL` を import できます。値はそれぞれ `0` / `1` です。
TypeScript の型も同じ名前で利用できます。

## 保存データと導出

Wallet Store の schema version は `1` のままです。Store と Pending Profile は
opaque byte 列として扱い、Application で解析・編集しないでください。
BIP39 passphrase は従来どおり空文字列に固定され、Profile password とは別です。
`symbol-sdk` と導出を比較するときに Profile password を BIP39 passphrase に使用しないでください。

## 責任分担の根拠

受領確認と確定要求の責任分担は [要件](../requirements/requirements.md#uc-001-profile-を作成復元する)
の UC-001、FR-001、AC-001、AC-034 に記載しています。
export / signing の assertion 契約はこの変更で削除されません。
